## 1. Что строим

AI-консультант для университета, проводящий онлайн-консультацию абитуриентов/студентов. Консультация состоит из **двух частей**:

1. **Профориентационный тест RIASEC** (модель Голланда, 6 типов: Realistic, Investigative, Artistic, Social, Enterprising, Conventional). Пользователь проходит тест → получает профиль (например «SAE») → рекомендации по направлениям подготовки вуза.
2. **Онлайн-консультация на базе знаний вуза (RAG)** — ответы на вопросы о программах, факультетах, поступлении, FAQ, грунтованные на реальном контенте вуза.

Обе части — это **один граф LangGraph** с роутингом между веткой теста и веткой RAG.

## 2. Стек (зафиксирован пользователем)

- **Python** — основной язык.
- **LangChain** — загрузчики, сплиттеры, обвязка LLM/эмбеддингов.
- **LangGraph** — оркестрация диалога (граф состояний: тест → скоринг → роутинг → RAG).
- **Qdrant** — векторная БД (поднимать в Docker).
- **OpenWebUI** — основной веб-фронт (подключается к бэку как pipeline/функция).

> Важно: Qdrant, LangChain, LangGraph — это **pip-библиотеки, не коннекторы**. Ставятся в песочнице/окружении проекта, плагин для них не нужен.

## 3. Каналы (решено с пользователем)

| Канал | Как делаем | Статус инструмента |
|---|---|---|
| **OpenWebUI** | Основной фронт, pipeline к бэкенду | в стеке |
| **WhatsApp** | Через **Twilio** | плагин Twilio Developer Kit установлен |
| **Telegram** | Бот на `python-telegram-bot` | код, готового MCP нет |

Все каналы — тонкие адаптеры к **одному** бэкенду (один граф, одна логика).

## 4. Источник знаний для RAG (решено)

Контент берём с **сайта вуза + локальных файлов** (PDF/docx). Готового коннектора к базе знаний нет — собираем скрейпером.

## 5. Установленные плагины/инструменты

- **Engineering** — system-design, architecture (ADR), code-review, testing-strategy, documentation, debug. Использовать для проектирования и ревью.
- **Twilio Developer Kit** — канал WhatsApp (+ Verify/OTP при необходимости).
- **Bright Data** — скрейпинг сайта вуза в чистый markdown (обход JS/бот-защиты) + структурированные данные из соцсетей (навыки `scrape`, `scraper-builder`, `data-feeds`, `search`, `brightdata-sdk`/CLI `bdata`).

Чего НЕТ как плагина и не нужно — препроцессинг для RAG (очистка, чанкинг, метаданные). Это код (см. §7).

## 7. Ingestion-пайплайн для RAG (всё — код)

`scrape → clean → chunk → metadata → upsert`

1. **scrape** — Bright Data (`bdata scrape` / SDK): страницы сайта вуза → markdown; локальные PDF/docx → `unstructured`.
2. **clean** — `trafilatura`/`unstructured` (основной текст), `ftfy`+regex (битые символы), дедуп по хешам.
3. **chunk** — `langchain-text-splitters`, рекурсивный по markdown-заголовкам с overlap; для длинных страниц — семантический чанкинг.
4. **metadata** — на каждый чанк: `source_url`, `title`, `faculty`, `program`, `doc_type`, `lang`, `updated_at`.
5. **upsert** — `qdrant-client`: коллекция, эмбеддер, батчевый upsert с payload + индексы для фильтров.

## 9. С чего начать в новом чате (порядок работ)

1. **Подтвердить открытые вопросы** (§10) с Isa.
2. **Поднять Qdrant** в Docker (`docker-compose.yml`) + создать окружение и поставить зависимости.
3. **RIASEC-тест** (можно параллельно): составить 42–48 вопросов под вуз, скоринг по 6 типам, маппинг профиль→направления подготовки. Сохранить в `riasec/`.
4. **Первый проход ingestion**: Bright Data scrape одной-двух страниц сайта вуза → clean → chunk → metadata → upsert в Qdrant. Проверить качество чанков.
5. **Скелет LangGraph**: state, узлы (тест / роутер / RAG), сборка графа.
6. **FastAPI бэкенд** поверх графа.
7. **Каналы**: сначала OpenWebUI, затем Telegram, WhatsApp, Meta.
8. По ходу фиксировать решения как ADR (`docs/adr/`) и писать тесты.

Рекомендуемый старт: пункты **2–4 параллельно**.
