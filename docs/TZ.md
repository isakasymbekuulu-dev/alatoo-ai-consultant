## 1. Общие сведения

### 1.1 Наименование системы
AI-консультант абитуриента — диалоговая система, объединяющая профориентационный тест по модели Голланда (RIASEC) и онлайн-консультацию по базе знаний вуза (RAG).

### 1.2 Назначение
Автоматизировать первичную профориентацию и справочную консультацию абитуриентов/студентов: помочь определить подходящее направление подготовки и ответить на вопросы о программах, поступлении, факультетах и стоимости, опираясь на реальные материалы вуза.

### 1.3 Цели
- Снизить нагрузку на приёмную комиссию за счёт автоматизации типовых вопросов.
- Повысить осознанность выбора направления (тест RIASEC + персональные рекомендации программ).
- Дать руководству вуза инструмент аналитики обращений и интересов абитуриентов.
- Обеспечить мультиканальный доступ (веб, мессенджеры) к единой логике.

### 1.4 Область применения
Приёмная кампания вуза, профориентация школьников и абитуриентов, информационная поддержка студентов.

## 2. Термины и сокращения

| Термин | Значение |
|---|---|
| RIASEC | Модель профессиональных интересов Дж. Голланда: Realistic, Investigative, Artistic, Social, Enterprising, Conventional |
| RAG | Retrieval-Augmented Generation — генерация ответа LLM с опорой на найденные фрагменты базы знаний |
| LLM | Большая языковая модель |
| Эмбеддинг | Векторное представление текста для семантического поиска |
| LangChain | Библиотека-обвязка для загрузчиков, сплиттеров, промптов и интеграции LLM/эмбеддеров |
| LangGraph | Библиотека оркестрации диалога в виде графа состояний (узлы и условные переходы) |
| Qdrant | Векторная база данных |
| Ingestion | Конвейер подготовки данных: scrape → clean → chunk → metadata → upsert |
| Код Голланда | Топ-3 типа интересов пользователя (например, «SAE») |

## 3. Описание системы

Система состоит из **единого бэкенда** (FastAPI) поверх **одного графа диалога** (LangGraph), к которому подключаются тонкие каналы-адаптеры. Граф маршрутизирует пользователя между двумя ветками:

1. **Профориентация (RIASEC):** 60 пунктов (адаптация O*NET Interest Profiler Short Form), шкала Ликерта 1–5, скоринг по 6 типам, код Голланда, маппинг профиля на программы бакалавриата вуза.
2. **Онлайн-консультация (RAG):** ответы на вопросы по базе знаний вуза (сайт + локальные PDF/docx), грунтованные на реальном контенте, с указанием источников.

Результаты теста привязываются к сессии чата и подмешиваются в контекст LLM, чтобы консультация была персональной.

## 4. Архитектура (целевая)

```
            Каналы-адаптеры
  ┌───────────────────────────────────────────┐
  │ OpenWebUI · Веб-чат · Telegram ·           │
  │ WhatsApp (Twilio) · Instagram/Facebook     │
  └───────────────────────┬───────────────────┘
                          │ единый REST API (FastAPI)
                          ▼
            ┌──────────────────────────────┐
            │     Граф диалога (LangGraph)  │
            │  state → router →             │
            │     ├── riasec_node           │
            │     └── rag_node (LangChain)  │
            └───────────┬──────────────────┘
                        ▼
        ┌───────────────────────┐   ┌──────────────────┐
        │ Qdrant (вектора, RAG) │   │ SQLite (логи,    │
        └───────────────────────┘   │ результаты теста)│
                                    └──────────────────┘
                        ▲
            ┌───────────────────────────┐
            │  Веб-админка: диалоги,     │
            │  результаты RIASEC,        │
            │  трассировки графа,        │
            │  аналитика                 │
            └───────────────────────────┘
```

Ключевой принцип: **каналы — тонкие адаптеры**, вся логика — в одном графе и одном API.

## 5. Функциональные требования

### 5.1 Профориентационный тест (RIASEC) — РЕАЛИЗОВАНО
- FR-1. Выдача 60 пунктов теста на трёх языках (ru/ky/en).
- FR-2. Ввод ФИО абитуриента перед началом (обязательное поле) для идентификации результата.
- FR-3. Сбор ответов по шкале 1–5; защита от пропуска вопросов; возврат к первому неотвеченному.
- FR-4. Скоринг по 6 типам, расчёт процентов выраженности, формирование кода Голланда (топ-3).
- FR-5. Маппинг профиля на программы бакалавриата вуза (топ-6 по конгруэнтности, веса 3/2/1).
- FR-6. Экран результатов: код, бары по 6 типам, описания ведущих типов, рекомендованные программы.
- FR-7. Экспорт результатов в PDF (через печать браузера), заголовки — на выбранном языке.
- FR-8. Согласие на обработку данных перед прохождением.
- FR-9. Сохранение результата в БД сразу при отправке, независимо от перехода в чат.
- FR-10. Передача результата в чат: кнопка «Обсудить с ИИ-консультантом», автозапуск обсуждения.

### 5.2 Онлайн-консультация (RAG) — РЕАЛИЗОВАНО (базово)
- FR-11. Приём вопроса пользователя через единый API, стриминговый ответ (SSE).
- FR-12. Семантический поиск релевантных фрагментов в Qdrant и формирование ответа LLM с опорой на них.
- FR-13. Подмешивание профиля RIASEC (если есть) в контекст для персонализации.
- FR-14. Указание источников/ссылок в ответе там, где применимо.
- FR-15. Если пользователь не знает, куда поступать — предложение пройти тест ссылкой `/test`.

### 5.3 Оркестрация (LangGraph) — К РЕАЛИЗАЦИИ
- FR-16. Единый граф состояний с узлами: `router` (классификация намерения), `riasec_node`, `rag_node`, `general_node`.
- FR-17. Условные переходы между узлами на основе намерения и наличия профиля RIASEC.
- FR-18. Сохранение потоковой выдачи ответа LLM (стриминг не должен ломаться при переходе на граф).
- FR-19. Журналирование маршрута каждого запроса (какие узлы и в каком порядке отработали) — для аналитики и отладки.

### 5.4 Подготовка знаний (LangChain ingestion) — К РЕАЛИЗАЦИИ/ДОРАБОТКЕ
- FR-20. scrape: страницы сайта вуза (Bright Data) → markdown; локальные PDF/docx → текст.
- FR-21. clean: очистка основного текста, исправление битых символов, дедупликация.
- FR-22. chunk: рекурсивный сплиттер по markdown-заголовкам с overlap (LangChain text-splitters).
- FR-23. metadata: на каждый чанк — source_url, title, faculty, program, doc_type, lang, updated_at.
- FR-24. upsert: батчевая загрузка в Qdrant с payload и индексами для фильтров.

### 5.5 Каналы — ЭТАПНО
- FR-25. OpenWebUI / собственный веб-чат — основной фронт (реализован веб-чат).
- FR-26. Telegram-бот (python-telegram-bot) — адаптер к единому API.
- FR-27. WhatsApp через Twilio — адаптер + вебхуки.
- FR-28. Instagram/Facebook через Meta Graph API — адаптер + вебхуки.

### 5.6 Веб-интерфейс управления и аналитики (админка) — ЧАСТИЧНО/К РАСШИРЕНИЮ
- FR-29. Список диалогов (сессий) с каналом, числом сообщений, временем, первым вопросом.
- FR-30. Просмотр полной переписки выбранной сессии.
- FR-31. Просмотр результатов RIASEC: ФИО, код, проценты, рекомендованные программы.
- FR-32. **Визуализация графа LangGraph** (узлы и переходы) в админке.
- FR-33. **Трассировка маршрутизации** по каждому диалогу: какое намерение определил роутер, через какие узлы прошёл запрос, какие фрагменты RAG были использованы.
- FR-34. **Аналитика:** распределение намерений, популярные вопросы/темы, распределение кодов Голланда, конверсия «тест → консультация».
- FR-35. Доступ к админке по токену.

## 6. Нефункциональные требования

- NFR-1. **Языки:** интерфейс и контент — русский, кыргызский, английский.
- NFR-2. **Производительность:** первый токен ответа RAG — в пределах нескольких секунд при типовой нагрузке; тест — мгновенный скоринг.
- NFR-3. **Приватность:** переписка обезличена; в веб-чате история не показывается другим пользователям (сессионное хранение); согласие на обработку данных фиксируется.
- NFR-4. **Безопасность:** rate-limit на публичных эндпоинтах; админка — за токеном; не запрашивать пароли/платёжные данные.
- NFR-5. **Надёжность:** ошибки каналов и LLM не роняют систему; деградация — понятное сообщение пользователю.
- NFR-6. **Сопровождаемость:** единая логика в графе; решения фиксируются как ADR; покрытие ключевой логики тестами.
- NFR-7. **Развёртывание:** Docker Compose (qdrant + backend + опц. openwebui); деплой на VPS/droplet.

## 8. Данные и хранение

### 8.1 SQLite
- `messages(id, ts, session_id, source, user_msg, assistant_msg, sources, consent)` — журнал реплик по сессиям и каналам.
- `riasec_results(id, ts, session_id, lang, code, scores, recs, consent, name)` — результаты теста, включая ФИО.

### 8.2 Qdrant
- Коллекция чанков базы знаний с payload-полями (source_url, title, faculty, program, doc_type, lang, updated_at) и индексами для фильтрации.

### 8.3 Трассировки графа (новое)
- Журнал маршрутизации: на каждый запрос — определённое намерение, последовательность узлов, идентификаторы использованных фрагментов RAG. Хранится в SQLite (расширение схемы) либо в отдельной таблице `graph_traces`.

## 9. Конвейер ingestion (RAG)

`scrape → clean → chunk → metadata → upsert`

1. **scrape** — Bright Data (`bdata scrape` / SDK): страницы сайта вуза → markdown; локальные PDF/docx → текст (unstructured).
2. **clean** — извлечение основного текста, исправление кодировки (ftfy + regex), дедуп по хешам.
3. **chunk** — LangChain `RecursiveCharacterTextSplitter`/по markdown-заголовкам с overlap; для длинных страниц — семантический чанкинг.
4. **metadata** — обогащение каждого чанка метаданными.
5. **upsert** — qdrant-client: батчевая загрузка с payload и индексами.

---

## 10. Веб-интерфейс управления (детализация)

Расширение существующей админки (`/admin`, доступ по токену):

1. **Диалоги** — список сессий, фильтры по каналу/дате, просмотр переписки.
2. **Результаты RIASEC** — таблица: ФИО, дата, код Голланда, проценты, рекомендованные программы; экспорт.
3. **Граф диалога** — статическая схема узлов и переходов LangGraph (визуализация структуры графа).
4. **Трассировки** — для каждого диалога: намерение роутера, путь по узлам, использованные фрагменты RAG (объяснимость ответа).
5. **Аналитика** — дашборд: число диалогов/сообщений, распределение намерений, топ-вопросы, распределение кодов Голланда, конверсия «тест → чат».

Цель раздела: дать пользователю (студенту-разработчику и вузу) возможность **контролировать и анализировать работу LangGraph/LangChain прямо через сайт**, без доступа к серверу.

## 13. Критерии приёмки

- AC-1. Тест RIASEC проходится на 3 языках, результат сохраняется с ФИО, выгружается в PDF на языке интерфейса.
- AC-2. Консультация отвечает по базе знаний вуза со стримингом; при наличии профиля RIASEC ответ персонализирован.
- AC-3. Диалог обрабатывается **через граф LangGraph**: в трассировке видны намерение и путь по узлам.
- AC-4. Ingestion использует **LangChain** (загрузчики/сплиттеры); чанки с метаданными загружены в Qdrant.
- AC-5. В админке доступны: список диалогов, переписки, результаты RIASEC, схема графа, трассировки, базовая аналитика.
- AC-6. Система развёрнута в Docker на VPS и обновляется через `git pull` + пересборку.
- AC-7. Ключевая логика (скоринг, API теста, маршрутизация) покрыта автотестами.

## 14. Риски и ограничения

- Качество RAG зависит от полноты и чистоты собранной базы знаний (этап ingestion критичен).
- Кыргызские формулировки теста требуют валидации носителем языка.
- Маппинг «профиль → программы» требует согласования с актуальным перечнем программ вуза.
- Перевод на LangGraph не должен ломать потоковую выдачу — обязательная проверка стриминга после интеграции.
- Лимиты внешних API (LLM, Twilio, Meta, Bright Data) — учитывать rate-limit и обработку ошибок.
