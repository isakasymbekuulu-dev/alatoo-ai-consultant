# ADR 0001 — Архитектура MVP AI-консультанта Ала-Тоо

Дата: 2026-06-07 · Статус: принято

## Контекст
Нужен рабочий MVP: абитуриент по ссылке **без авторизации** открывает чат и
консультируется по данным вуза (RAG). Профориентационный тест RIASEC — позже.
Данные на старте — локальные файлы (PDF/DOCX/TXT/MD), без скрейпинга сайта.
У пользователя уже есть дроплет DigitalOcean (там подняты OpenWebUI и Qdrant)
и подписка GitHub Education.

## Решения

1. **LLM — GitHub Models** (`openai/gpt-4o-mini`) через OpenAI-совместимый эндпоинт
   `https://models.github.ai/inference`. Бесплатно по GitHub Education (есть лимиты).
2. **Эмбеддинги — BGE-M3** (`BAAI/bge-m3`, dim 1024), мультиязычный (ky/ru/en),
   запускается локально в контейнере бэкенда (CPU). Один и тот же эмбеддер на
   индексации и на запросе.
3. **Векторная БД — Qdrant** в Docker с **именованным volume** (`qdrant_data`).
   Данные переживают перезапуски/редеплой — отвечает на требование «БД не стирается».
4. **Бэкенд — FastAPI**, отдаёт **OpenAI-совместимый** `/v1/chat/completions`
   (+ `/v1/models`). Внутри: ретрив из Qdrant → промпт с источниками → генерация.
   Один бэкенд — единая точка для всех каналов.
5. **Публичный доступ без логина — отдельная лёгкая страница чата** (`/`),
   которую отдаёт сам бэкенд. Причина: OpenWebUI **не поддерживает анонимный вход**
   (любой по ссылке упирается в логин — подтверждённое ограничение проекта).
6. **OpenWebUI** подключается к бэкенду как OpenAI-модель (`OPENAI_API_BASE_URL`)
   и используется сотрудниками/для админ-тестов (с логином).

## Последствия
- Анонимный сценарий абитуриента работает сразу (страница `/`), OpenWebUI сохранён
  для внутреннего использования — оба фронта бьют в один бэкенд и одну базу знаний.
- BGE-M3 требует ~3–4 ГБ RAM. Если дроплет маленький — переключиться на
  `intfloat/multilingual-e5-small` (dim 384) через `EMBED_MODEL`/`EMBED_DIM`.
- Лимиты GitHub Models могут упереться при нагрузке → запасной путь: ключ OpenAI
  (тот же код, меняется только `*_BASE_URL` и `LLM_MODEL`).

## Отложено (следующие шаги)
- Профориентация RIASEC как ветка LangGraph.
- Скрейпинг сайта (Bright Data) для пополнения базы.
- Каналы Telegram / WhatsApp(Twilio) / Meta как тонкие адаптеры к тому же `/v1`.
- TLS + домен (nginx/Caddy), rate-limiting и ключ на публичный эндпоинт.
